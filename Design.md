# Matchmaker Plugin Design System & Match Lifecycle

This document defines the official design tokens, typography, CSS component styles, and match status lifecycle rules for the Matchmaker plugin (sourced from `update.md`).

---

## 1. Match Status Lifecycle & Assignment Rules

The matchmaking lifecycle in `wp_matches` uses two distinct layers: **Global Match Status** (`status`) and **Directional User Responses** (`user_one_response`, `user_two_response`).

### Global Match Statuses (`status`)

| Status | When to Assign | Trigger / System Event | Quota Impact |
| :--- | :--- | :--- | :---: |
| **`pending_review`** | Initial state when candidate pairs are generated by the matching algorithm. | Enqueued by Action Scheduler or manual admin trigger. | **0** (No quota deducted) |
| **`approved`** | When an admin approves a `pending_review` pair for subscriber visibility. | Admin clicks **Approve** in Admin Portal (requires quota count $< 10$). | **+1** to `cycle_matches_count` |
| **`admin_rejected`** | When an admin disallows a proposed match before users see it. | Admin clicks **Reject** in Admin Portal. | **0** (Quota preserved) |
| **`matched`** | When **both** paired users accept the match proposal. | `user_one_response = 'accepted'` AND `user_two_response = 'accepted'`. | Unlocks contact info (`contact_revealed = 1`) |
| **`rejected`** | When **either** user declines an approved match. | Either `user_one_response = 'rejected'` OR `user_two_response = 'rejected'`. | Profile moves to archived matches. |

### User Response States (`user_one_response` / `user_two_response`)

* **`pending`**: Default state assigned at pair creation. The user has not yet accepted or rejected the candidate proposal.
* **`accepted`**: User approves the match proposal on their dashboard. If the other user has already accepted, status automatically transitions to `matched`.
* **`rejected`**: User passes on the candidate. The global match status immediately switches to `rejected`.

## 2. Design System Guidelines

### Color Palette

| Token | Hex Value | Role & Primary Application |
| :--- | :--- | :--- |
| **Primary** | `#CC723F` | Primary buttons, active stepper indicators, selected dropdown items, active tabs. |
| **Secondary** | `#F8F2ED` | Form section backgrounds, card containers, dropdown hover states, zebra striping. |
| **Accent** | `#CC723F` | Section icons, interactive focus borders, primary brand accents. |
| **Secondary Accent** | `#829067` | Success alerts, `matched` / `approved` status badges, confirmation tags. |
| **Text** | `#000000` | Headings, primary labels, body text, form field inputs. |
| **White** | `#FFFFFF` | Form wrapper background, active input fields, modal containers. |
| **Black** | `#000000` | Borders, subtle divider accents, primary headers. |

---

### Typography Rules

* **Display / Headings**: `'Cormorant SC', serif`
  * **H1 / Page Titles**: `32px` · Regular (400) / Semi-Bold (600) · `letter-spacing: 1.5px` · Uppercase
  * **H2 / Form Sections**: `22px` · Regular (400) · `letter-spacing: 1px` · Uppercase
  * **H3 / Card Headers**: `18px` · Medium (500) · `letter-spacing: 0.5px`
* **Body Text & UI Elements**: `'Inter', sans-serif`
  * **Field Labels**: `13px` · Medium (500) / Semi-Bold (600) · Uppercase · `color: #000000`
  * **Input & Select Text**: `14px` · Regular (400) · `color: #000000`
  * **Descriptions & Subtitles**: `13px` · Regular (400) · `color: rgba(0, 0, 0, 0.65)`
  * **Button Labels**: `14px` · Semi-Bold (600) · `letter-spacing: 0.5px`
